Lifecycle

Custom UI orchestrates the path. MLflow keeps the system of record for runs, artifacts, and the registry.

01 · Experiment

Create or select an experiment

Training and evaluation runs live in one MLflow Tracking experiment. Production is later a registry alias on this same MLflow instance — not a second experiment.

    02 · Dataset

    Load a synthetic classification split

    Tiny sentiment data (positive / negative / neutral). Primary metric is macro F1.

    Uploads need columns split (train|test), text, and label.

    Split Text Label

    03 · Model

    Attach a prompt to an LLM

    Define the classifier here: system prompt plus the LLM (or local heuristic). Train later runs this definition and logs F1 — it is not where you first write the prompt.

    Use {labels} in the template to inject the dataset label set.

    04 · Train

    Evaluate the saved model and log it to MLflow

    Runs the Model-step definition on the selected dataset. Overrides are optional. Each run logs params, prompt text, F1, and a pyfunc model.

    05 · Evaluate

    Compare runs by macro F1

    Metrics are stored on the MLflow run. Use the deep links for artifacts, traces, and the full UI.

    Run Model Prompt F1 macro Precision Recall Accuracy

    06 · Promote

    Finalize a model via the registry

    Promotion assigns a Model Registry alias (champion / challenger) on the same MLflow server. That is the production pointer — not a new experiment.

    07 · Production

    Serve models:/name@champion

    Inference loads the alias. Optional MLflow traces land in workbench-production-traces for monitoring — they are not training runs.
